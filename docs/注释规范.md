# 代码注释规范

本文档定义本仓库全部 Python 代码的注释与 docstring 标准，供后续维护统一执行。
核心原则一句话：**注释解释"为什么"与"边界条件"，代码表达"做什么"**；注释只增删
"注释与 docstring"，绝不改动可执行语句、字符串字面量、日志格式、函数签名与常量。

## 一、模块头 docstring（每个 .py 文件必有）

```
"""<一句话说明本模块职责>。

<2~6 行补充: 核心职责 / 对外接口 / 关键不变量 / 依赖关系，按需择要>。

本模块约定:
- <关键设计约定，每条一行；没有约定可省略本小节>
"""
```

- 一律简体中文；一行职责句不加句号以外的多余标点，正文句末加句号。
- 已有 docstring 的信息不得丢失：只按本模板补全/微调格式，不重写语义。

## 二、章节分隔线

每个逻辑区块前用统一分隔线（与仓库既有风格一致）：

```python
# ---------------------------------------------------------------------------
# 章节标题
# ---------------------------------------------------------------------------
```

- 分隔线长度与文件内主流风格对齐（通常 75 个 `-`）。
- 章节标题为中文短句，不加标点；同一文件内风格统一。
- 扁平小模块（无内部逻辑分区的纯函数/纯常量列表）可不加分隔线，
  以"文件内风格统一、不增无意义噪音"为准。

## 三、类 / 函数 docstring

- 所有公开类：必须有中文 docstring，说明职责与关键规则。
- 所有公开方法 / 函数：必须有中文 docstring；一句话说清"做什么"，
  有非显然行为时补一句"为什么 / 边界条件"。
- 私有方法（下划线开头）：已有 docstring 的保留并统一为中文；
  缺 docstring 的仅在逻辑非显然时补一句话，不为了凑数硬写。
- 不写冗长的 `:param:` / `:return:` 段落，参数与返回值在正文中自然说明。

## 四、行内注释

- 只保留解释"为什么"的注释；与代码同义、纯描述"做什么"的行内注释直接删除。
- 行内注释一律中文，置于所解释代码的上一行或同行，缩进与代码对齐。
- 既有的英文注释统一译为中文；注释中的专有名词（QMT / Redis / signal_id /
  worker / pending / ACK 等）保留原文。

## 五、日志与命名

- 日志字符串是业务输出，**一字不改**（含 emoji 风格与格式占位符）。
- 变量、函数、类名一律不改名（重命名属于行为变更，另行评审）。

## 六、禁止事项

1. 禁止修改任何可执行语句、表达式、字符串字面量、函数签名、常量数值、import。
2. 禁止为凑格式重排语句顺序或调整缩进语义。
3. 禁止改动 `.py` 以外的文件（AGENTS.md / CLAUDE.md / README.md / YAML 等）。
4. 每改完一个文件必须通过 `python -m py_compile <文件>` 语法校验。
5. 不运行测试套件、不执行 git 操作、不 import 本仓库模块运行任何逻辑。

## 七、测试代码的放宽规则

`tests/` 为本地套件，只做轻量标准化：

- 缺模块 docstring 的补一句中文职责说明；缺类 docstring 的补一句。
- 测试方法 docstring 仅在"方法名无法说清被测行为"时补一句话。
- 测试逻辑、断言、mock 参数、字符串一律不动。
- 已符合规范的测试文件保持原样并在交付摘要中说明。
