# QMT 开盘预约 ETF 买入设计

## 目标

解决聚宽实时模拟盘到真实交易信号约 10 秒的延迟。`ETF稳健折价猎手` 在 09:25–09:30 之间完成目标 ETF 选择后，立即把调仓信号发送给 QMT：旧 ETF 卖单立即进入集合竞价，目标 ETF 买单由 QMT 缓存至本机 09:30:00 再提交。

## 范围与约束

- 只修改 `ETF稳健折价猎手` 的实盘开盘信号时序和 miniQMT 执行端对预约信号的调度。
- 保持 `publish_trade_signal_to_redis(context, action, code, amount, price)` 五参数公开签名不变。
- 保持 Redis Stream、`signal_id` 幂等、全局 FIFO、行情定价、价格偏差保护、资金/持仓封顶、撤单和重试逻辑。
- 不修改其他策略的早盘执行时序。
- 不新增依赖、配置项、数据库表或公开 API。
- 回测保持原有 09:30 折价收敛二次验证和交易逻辑。

## 聚宽端数据流

### 09:25 开盘调仓计划

`generate_raw_signal()` 在成功得到初选结果后，继续推送目标与当前持仓的行情预订阅，并仅在 `mode=live` 时生成提前交易信号。

1. 目标集合是 09:25 按折价从深到浅选出的 ETF。
2. 当前持仓中不在目标集合的 ETF，按当时持仓数量立即发布普通卖出信号。该信号不带预约时间，QMT 按现有竞价保护逻辑立即向券商提交。
3. 买入目标值使用聚宽影子账户总资产和现有仓位上限计算。多目标时沿用折价绝对值权重；当前配置 `max_holdings=1` 且 `single_position_cap=1` 时，等价于单只 ETF 满仓目标。
4. 买入数量按 `目标市值 / 09:25参考价` 向下取整到 100 股，再减去已有目标 ETF 持仓。结果不大于零时不发买单。
5. 买入信号增加可选字段 `execute_at="YYYY-MM-DD 09:30:00"`，其 `expire_at` 以 `execute_at` 为基准顺延现有过期秒数。
6. 明确选股成功但目标集合为空时，按现有语义提前卖出全部旧持仓，不生成买单。
7. 候选池不可用或选股异常时，不猜测开盘计划，保留原有 09:30 异常路径和错误日志。

### 09:30 聚宽影子账户同步

- `mode=live` 时不再做折价收敛二次过滤，直接使用 09:25 选定的目标。
- 聚宽仍在 09:30 执行本地模拟调仓，以保持影子持仓状态供后续交易日使用。
- 每笔 09:25 信号只有在 Redis `XADD` 成功后才记为“已提前发布”。聚宽 09:30 影子调仓不再重复发布这些已成功的同代码、同方向信号。
- 某笔提前信号发布失败时，不将其标记为已发布；09:30 影子调仓仍会按现有路径尝试发送该笔信号并留下清晰日志。
- 已提前发布标记在 09:30 影子调仓后清理，不影响 14:25 止损止盈信号。

## Redis 信号合同

`TradeSignal` 新增一个可选字段：

```json
{
  "execute_at": "2026-07-13 09:30:00"
}
```

- 缺省或空值表示立即执行，因此所有旧信号和其他策略保持原行为。
- 字段使用 QMT 所在机器的本地时区解释，聚宽和 Windows 必须保持 NTP 同步。
- 无法按 `%Y-%m-%d %H:%M:%S` 解析的非空值是非法信号，直接报错，不降级为立即交易。
- `execute_at` 只控制何时进入现有执行引擎，不改变最终委托价、数量封顶或终态处理。

## QMT 端调度

QMT 应用层保存尚未到期的 `StreamMessage`，不在执行引擎或工作线程内 `sleep`。

1. 每次 Redis 读取轮询都先检查预约列表。
2. `execute_at` 已到或在过去的信号立即提交给单工作线程。
3. 尚未到期的信号继续留在应用层，不阻塞 Redis 收信、行情预订阅和其他即时交易信号。
4. 到期后按 `execute_at` 和 Redis 消息 ID 的稳定顺序提交，再由现有单线程 FIFO 执行。
5. Redis `block_ms` 当前默认为 20ms，因此正常空闲时的到期调度偏差为约 0–20ms，不引入新的调度线程。
6. Redis 消息在预约等待期不 ACK；只有执行引擎进入终态后才沿用现有流程 ACK。
7. 正常关闭时不提前执行未到期买单，未 ACK 的 Redis 消息保留为待处理状态。

## 异常处理

- 聚宽发布失败：使用现有错误日志，不伪造成功标记，09:30 保留单笔降级发信机会。
- 买入数量不足 100 股：不发布买单，记录原因。
- QMT 解析到非法 `execute_at`：记录异常并保留 Redis 未确认状态，不立即下单。
- 09:30 旧仓卖单尚未终态：预约买单按 FIFO 等待，不并行绕过资金约束。
- 卖出后资金仍不足：现有执行引擎按最新可用资金向下封顶到 100 股整手；无可买数量时风控失败。
- 参考价到开盘最新定价偏离超限：继续使用现有 `max_deviation_from_signal_price_pct` 拒绝交易，不因抢单需求降低风控。
- QMT 在预约等待期退出：本次实现不新增持久化调度表；Redis 消息保持未 ACK。恢复后的 pending 自动重领可作为独立后续增强，不与本次开盘时序修改捆绑。

## 日志

- 聚宽：记录提前卖出、预约买入、目标数量、`execute_at`、发布结果和 09:30 重复信号抑制。
- QMT：收到预约信号时记录预约时间和剩余毫秒；到期时记录调度偏差；后续下单与终态日志沿用现有格式。
- 日志不输出 Redis 密码或其他凭证。

## 测试与验收

### 聚宽策略回归测试

- 实时 09:25 选中目标后，旧持仓发布立即卖单，目标 ETF 发布带 09:30 `execute_at` 的买单。
- 买入数量是 100 股整手，已有目标持仓会从计划数量中扣除。
- Redis 发布成功的早盘信号不会在 09:30 重复发布；失败的单笔仍可在 09:30 发送。
- `mode=live` 的 09:30 路径不再执行收敛过滤，回测路径保持原过滤。

### QMT 单元测试

- `TradeSignal.from_dict()` 可解析有/无 `execute_at` 的信号，旧信号默认立即执行。
- 未到期信号不调用 `OrderExecutionEngine.execute()`，也不 ACK。
- 到期和过期信号按稳定顺序提交给单工作线程。
- 等待预约买单不阻塞普通即时信号和 watchlist 处理。
- 只有执行终态后才 ACK 预约信号。

## 兼容性和已知风险

- 所有无 `execute_at` 的旧消息保持立即执行，其他策略无需修改。
- 旧 ETF 未在开盘及时成交时，买单受 FIFO 和实际可用资金约束，不能保证绝对的 09:30:00 券商受理时间。
- QMT 本机时间错误会直接影响调度时刻；上线前必须确认 Windows 时间同步。
- 预约列表本次不增加本地持久化。正常运行时 Redis 未 ACK 消息可防止误确认，但进程重启后自动恢复 pending 预约单不在本次范围内。
- 策略文件位于 Git 忽略的 `strategies/` 目录，修改会在本地生效但不会自动出现在普通 `git status` 中。
